### Here are a few tech opinions I stand by:

**Small Language Models** like Qwen 2.5 3B or Llama 3.2 3B are the *future* of AI. 
I believe that the industry will shift toward smaller, more efficient models that specialise 
in certain topics rather than big, multi-trillion parameter models that function as 
*"Jacks of all trades, masters at none."*

The **next frontier** of Red Teaming and hacking lies in *social engineering*.
I say this because as AI gets better at finding zero days, defenders will 
be able to patch vulnerabilities faster than attackers can exploit them—**rather
than the opposite**. Hence, attackers will turn towards the weakest link in a system
that cannot be patched: the *human mind*. Tricking a help desk into resetting a 
password will always be *significantly cheaper* than spending months on exploit development.

**Using AI** to code is *completely acceptable* under certain conditions. I believe AI is an excellent
force multiplier when it comes to coding but can only be used under these conditions:

* You only use the AI to write syntax, and you manually design **how** the system works, shifting from an engineer to architect
* You are aware that AI generated code tends to be *insecure* if not explicitly told to use specific secure methods
* You always review, test, security check the AI generated code yourself
**TL;DR**, you use AI as a regular engineer, while you graduate to an architect and tester
